## 프롬프트 본문 (여기부터 붙여 넣는다)

이 지시서는 Fable 5.1 기준으로 썼다(가이드 확인일 2026-09-29). 세션 모델이 다르면 시작 전에 사용자에게 알린다.

### 맡는 일
- 과제 `P03` · 세션 `S3` · 스트림 판정 · 마일스톤 없음.
- 두 실행 세션(S1 Sonnet 5.5 · S2 Opus 5.5)이 같은 지시서([S1·S2](20261031_S1S2_Unity_P03_실행.md))로 만든 브랜치 `p03/exec-sonnet` · `p03/exec-opus` 를 **검산**하고 비교표로 정리해 사용자가 하나를 고르게 한 뒤, 고른 브랜치를 `main` 에 넣고 P03 을 닫는다. 왜: 이 과제는 CLI 파이프라인 확인이면서 두 모델의 비교 실험(D-04 · D-05)이다 — 보고를 믿지 않고 산출물로 확인하는 것이 핵심이다(루트 `CLAUDE.md` 「에이전트 보고」).

### 성공 기준 · 위험 · 되돌리는 법
- **성공 기준**:
  1. 비교표 `03_작업기록/비교표_<날짜>.md`(`doc_type: review` · static) — D-05 아홉 항목 × 두 브랜치. 항목마다 **검산한 산출물**(파일 · 명령 출력)을 근거로 적고, 보고의 주장과 실제가 다른 곳을 따로 표시한다. 사용자 기록(시간 · `/cost` · 멈춤 · 개입 횟수)을 받아 넣는다.
  2. 사용자가 브랜치를 골랐고(또는 「둘 다 아님」), 고른 브랜치를 `main` 에 `--no-ff` 로 머지(`merge: [P03] <모델> 실행 브랜치 — 비교 판정`), 머지 뒤 닫힘 게이트 1회 통과. 다른 브랜치는 비교표에 해시를 적고 삭제(번들 `z.tmp/p03_results/` 는 둔다).
  3. `Defense.Unity/CLAUDE.md` 「결정론 게이트」에 고른 브랜치가 실측한 캡처 · 에디터 렌더 명령을 더하고 정본 `_템플릿/Unity_CLAUDE.md` 와 `cmp` 같음(D-07).
  4. Planning 으로 이관 — 두 브랜치의 센서 기록(`z.docs/work_reports/<날짜>/코드리뷰_<모델>/`)을 `03_작업기록/코드리뷰_<날짜>_<모델>/` 로, 진 브랜치의 작업 보고 · 캡처 README 를 `03_작업기록/실행_<모델>/` 로(이긴 쪽은 `main` 에 있다). 캡처 원본은 `z.captures/<날짜>/<모델>/` 로 되돌려 둔다(git 밖).
  5. P01 NOTES 4번의 `DEF-M03` 메모를 두 보고의 「발견」으로 갱신(클립 이름 · 루트 회전 · 캡처 가능 여부 · 명령 · 시간).
  6. 종결 — `_도구/코드리뷰_집계.py --task P03` → `지표.md` 한 행 · 작업색인 · 과제 README 상태 · 현황판 · 지시서 `_old/` · `z.completed/` 로 `git mv`. 사용자 「확인」 한 줄(D-08)을 결정기록에.
- **위험 등급**: 저(문서 · 머지 · 기록 이관). 머지되는 내용은 S1 · S2 의 저위험 변경. **되돌리기**: 머지 커밋 `git revert -m 1`.
