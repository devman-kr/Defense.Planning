# P03 과제 계획서 — CLI 환경 시험(Blender · Unity)과 Sonnet 5.5 · Opus 5.5 비교 실행

**근거** [검토서](../01_검토/검토서_20261031.md) · [결정기록](../결정기록.md) D-01~D-10 반영 · 기획 정본 `../../../Defense.Design/기획서.md` v0.4(5절 적 · 9절 아트 — 이 과제는 기획서를 고치지 않는다)
**규모 표기**: S = 반나절 이하 · M = 1~2일 · L = 3일 이상

**이 문서의 위치**: 검토서의 방안 B(D-01)를 세션 넷으로 쪼갠다. 저장소는 `Defense.Unity`(시험 씬 · 에셋 · 에디터 스크립트 · `Tools/Blender/` — D-02 · D-09) · Planning(이 폴더). Design 은 손대지 않는다. 마일스톤 문서는 없다 — 저장소 제품 코드를 바꾸지 않는 시험 과제라 이 계획서와 지시서가 상세의 정본이다. 특이점은 **실행을 두 모델(Sonnet 5.5 → Opus 5.5)이 같은 입력으로 따로 한다**는 것(D-04)이고, 그래서 「같은 입력」을 2절 계약으로 못 박고, 사이사이의 격리 절차를 6 · 7절에 사용자 손 절차로 둔다.

## 6. 환경 · 자원

빈 번호 폴더는 git 이 추적하지 않아(`.meta` 만 있다) worktree 에 없다 — 에디터가 고아 `.meta` 를 지우지 않게 미리 만든다. **(a) 는 `sonnet` · `opus` 둘 다 2026-10-31 계획 세션이 끝냈다**(사용자 제안 — worktree `z.tmp/wt/p03-sonnet` · `p03-opus` 모두 `763866b`, `Library/` 클론 각 7초, 빈 번호 폴더 셋 · `Logs/`). 캡처 폴더 `z.captures/<날짜>/<모델>/` 는 실행 세션이 그날 날짜로 만든다(`20261031/sonnet/` 은 미리 만든 빈 폴더 — 날짜가 다르면 지운다). S1 동안 `p03/exec-opus` 브랜치가 보이지만 내용은 시작 커밋과 같아 새어 나갈 정보가 없다. (b) 에서 지우는 것은 **sonnet 쪽만**이다.
세션은 작업 공간 루트에서 연다(훅). `/model sonnet` · `/effort high`. 지시서 본문을 붙여 넣는다. **시작 시각**을 적어 둔다.

**(b) S1 뒤 — 격리(S2 가 보지 못하게)**: 세션이 끝나고 푸시 질문에 답한 뒤(푸시는 하지 않는다 — 브랜치는 로컬), `/cost` 출력과 **끝 시각** · 멈춤 · 질문 횟수를 적어 둔다. 그리고
```
mkdir -p z.tmp/p03_results/sonnet
git -C Defense.Unity bundle create "$PWD/z.tmp/p03_results/sonnet/exec-sonnet.bundle" p03/exec-sonnet
git -C Defense.Unity worktree remove --force "$PWD/z.tmp/wt/p03-sonnet"

mv "z.captures/<날짜>/sonnet" z.tmp/p03_results/sonnet/captures
```
`git -C Defense.Unity branch` 에 `p03/exec-sonnet` 이 없는지 본다. 그 다음 (a) 를 `opus` 로 반복.

**(c) S2 뒤 — 같은 격리**(`opus` 로). 둘 다 번들에 있다.

**(d) S3 전 — 복원**
