# P04 매끈한 모델 시험 검토서 — 로우폴리 샘플을 서브디비전 매끈 판으로 다시 만들어 셰이딩 3종으로 비교하기

**이 문서의 위치**: 사용자 요청(2026-11-02) 「현재 데모 모델은 전부 로우폴리인데 실제 이용하고 싶은 모델링은 매끈매끈한 캐릭터다. 레퍼런스(Supercent)의 캐릭터 · 모델도 로우폴리가 아니라 매끈 · 둥글다. 블렌더에서 제작하고 유니티에서 확인하는 로직을 다른 세션의 Opus 가 진행할 수 있게 지시서를 써 달라」를 과제 P04 로 여는 검토다. 결정 경위는 [결정기록.md](../결정기록.md). 실측은 하지 않았다 — 현재 상태는 문서와 P03 산출물로 확인했다.

**읽는 사람**: 결정자(1 · 5 · 6절) · 실행 세션(4절 — 지시서가 가리킨다).

**용어**: 로우폴리 판 = P03 이 만든 샘플 3종(면이 각지고 플랫) · 매끈 판 = 같은 모델을 서브디비전 + 스무스 셰이딩으로 다시 만든 것 · 셀 = 툰 램프 셰이더.

---

## 1. 결론

- 매끈 판을 **같은 CLI 파이프라인으로 만들어 그림으로 비교**한다. 기법은 서브디비전(Subdivision Surface) + 스무스 셰이딩, 팔레트 셀 단색 유지(4절). 두 세션으로 나눈다 — S1 기존 셋 매끈 판 · 함정 실측 · 셰이딩 3종 캡처, S2 해골 궁수 · 좀비 인간형.
- 아트 방향(기획서 9절 · 스타일 보드 3 · 4절 · `_공통` G-02 문구)은 이 과제가 고치지 않는다. 결과를 본 사용자가 6절의 여섯 가지를 결정한다.
- 빼는 것: 스컬프트 · 리메시, CC0 매끈 모델 탐색, 아웃라인 셰이더, 플레이 모드 · 애니메이터 컨트롤러, 기기 성능 측정(모두 4절 또는 `DEF-M03`).

## 6. 뒤에 결정할 것 (S1 · S2 결과 뒤 — 결정기록 「미결」)

1. 아트 방향 — 매끈 판 채택 여부, 기획서 9절 · 스타일 보드 3 · 4절 정정, 세 게임 공통이면 G-nn(G-02 「Blender 로우폴리」 문구).
2. 폴리곤 예산 — 서브디비전 1 · 2단계 중 기준, 캐릭터당 삼각형 상한(동시 생존 적 상한 300 과 함께).
3. 좀비 등재 — 기획서 5절 적 목록에 넣는가.
4. 셰이딩 채택 — Lit · Unlit · 셀.
5. 에셋 공급원 — 매끈 판이면 Quaternius 로우폴리 팩 1순위가 맞지 않을 수 있다.
6. P03 로우폴리 샘플의 운명.

## 7. 위험과 전제

- **성능** — 매끈 판은 삼각형이 케이지의 4~16배다. 동시 생존 적 300(기획서 5절) 기준으로 S1 보고에 「삼각형 수 × 300」을 적게 했다. 실제 예산 · LOD 는 `DEF-M03`. 스킨 메시 300 개의 CPU 비용은 모델 밀도와 무관하게 따로 남는 문제다(이 과제 밖).
- **셀 셰이더 유지** — URP 버전이 오르면 손 셰이더가 깨질 수 있다. 채택하면 `DEF-M03` 이 Shader Graph 전환 여부를 정한다. S1 은 「컴파일 경고 0」까지만.
- **베타 도구** — Unity CLI 1.0.0-beta.13 · `com.unity.pipeline` 0.9.1 은 P03 과 같은 판이어야 한다. 바뀌었으면 S1 보고 「지시서와 다른 점」.
- **레퍼런스 접근** — 스토어 페이지가 스크립트 접근을 막으면 글 설명만으로 진행한다(지시서에 적음). 공통 실행 요청 5(사용자 캡처)는 그대로 대기.
- **범위 유혹** — 인간형이 들어가면 Hit · Die · 애니메이터 컨트롤러 · 플레이 모드까지 가고 싶어진다. 전부 범위 밖으로 적었다.
- 전제: `Defense.Unity` `main` HEAD `43dc1c7`, Blender 5.2.3, Unity 6000.3.27f1, 한 기기(Blender 와 에디터를 같이 띄우지 않음 — G-01).
