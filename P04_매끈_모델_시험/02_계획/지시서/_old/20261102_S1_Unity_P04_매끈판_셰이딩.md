## 프롬프트 본문 (여기부터 붙여 넣는다)

이 지시서는 Claude Opus 5.5 기준으로 썼다(가이드 확인일 2026-09-29). 세션 모델이 다르면 시작 전에 사용자에게 알린다.

### 맡는 일
- 과제 `P04`(매끈한 모델 시험) · 세션 `S1` · 스트림 B(Unity) · 마일스톤 없음(저장소 제품 코드를 바꾸지 않는 시험).
- 지금 샘플 모델 3종(슬라임 · 박쥐 · 등불 탑 — `Tools/Blender/make_enemies.py` 산출, 로우폴리 · 플랫)을 **매끈하고 둥근 판**으로 다시 만든다. Blender 를 창 없이 돌려 같은 뼈대 · 같은 동작 · 같은 팔레트 셀로 서브디비전 + 스무스 셰이딩 판을 만들고 FBX 로 내보내, Unity 샘플 씬에 로우폴리 판과 나란히 놓고 URP Lit · URP Unlit · 셀 세 셰이딩으로 캡처한다. 끝나면 사용자가 「매끈 · 둥글」이 이 파이프라인에서 어떻게 나오고 셰이딩마다 어떻게 달라 보이는지 그림으로 고를 수 있고, 매끈 판의 함정(서브디비전 뒤 스킨 가중치 · 노멀 · 팔레트 UV · 삼각형 수)이 실측값으로 남는다. 이 결과로 **사용자가** 아트 방향(기획서 9절 · 스타일 보드)을 정한다 — 이 세션은 정하지 않고 고치지 않는다.
- 목표하는 결(레퍼런스 Supercent 의 캐릭터): 면이 각져 보이지 않는 둥근 덩어리, 머리 · 손이 큰 비례, 점 눈, 밝은 원색 · 파스텔의 면 단위 단색(그라데이션 텍스처 없음), 부드러운 그림자, 외곽선 없음. 세션은 아래 「레퍼런스 보기」 절차로 공개 스크린샷을 보고 관찰을 글로 남긴다.

### 진행 방식
- 사용자는 세션을 지켜보지 않는다. 요청한 것이 끝날 때까지 계속하고, 「금지」 · 「계약」에 걸리는 일이나 사용자 없이는 못 나아가는 일 앞에서만 멈춘다. 다음 단계를 예고만 하고 턴을 끝내거나, 작업을 막지 않는 결정을 묻거나, 한 구간이 끝났다고 보고하러 멈추지 않는다 — 구간 결과는 작업 보고에 쓴다.
- 지시는 적힌 대상 전부에 적용한다 — 「모델 3종」이면 슬라임 · 박쥐 · 탑 모두, 「셰이딩 3종」이면 Lit · Unlit · 셀 모두, 「두 판」이면 매끈 · 로우폴리 모두.
- 더 나은 방법이 보이면 보고에 한 문장으로 적고, 요청대로 진행한다. 요청하지 않은 기능 · 테스트 · 파일 · 문서 · 리팩터링은 하지 말고 끝에 제안으로 적는다.
- 실행 · 컴파일 · 테스트를 돌릴 수 있는 변경은 실제로 그 변경을 거치는 검사를 돌린 뒤 완료로 적는다. 못 돌렸으면 무엇을 왜 못 돌렸는지 적는다.
- 미지수(「참고 사실」 끝의 다섯)는 **실측해서 숫자 · 오류 원문으로** 남기는 것이 이 세션의 일이다. 하나가 막히면 원인을 한 번 바꿔 시도하고, 그래도 막히면 그 항목을 「막힘 — 오류 원문」으로 적고 다음으로 간다. 같은 오류를 세 번 넘게 반복하지 않는다.
- 시작 전 한 줄(「지시서와 다른 점」 — 없으면 「없음」)을 사용자에게 알리고 바로 착수한다. 작업 중 사용자에게 쓰는 글은 짧게, 마지막 보고는 그것만 읽어도 되게(「보고 형식」).

### 성공 기준 · 위험 · 되돌리는 법
- **성공 기준**(확인 방법을 붙였다 — 리뷰 센서는 이 조건에 대조한다):
  1. **Blender 매끈 판 스크립트** `Tools/Blender/make_enemies_smooth.py`(새 파일. `make_enemies.py` 의 도우미를 복사하거나 공통 모듈로 뽑되, 뽑았으면 `make_enemies.py` 를 한 번 돌려 `P03_RESULT` 와 FBX 크기가 전과 같음을 보고에 적는다): `Blender -b --factory-startup -noaudio --python-exit-code 1 --python Tools/Blender/make_enemies_smooth.py -- z.tmp/p04_out` 이 종료 0. 슬라임 · 박쥐 · 탑을 **같은 뼈대 · 같은 동작(슬라임 Idle · Hop · Hit · Die, 박쥐 Flap · Hit) · 같은 팔레트 셀**로 서브디비전(캐릭터 2단계) + 스무스 셰이딩, 탑의 각진 부분은 베벨 또는 크리스로 둥글되 기둥 · 지붕의 윤곽이 읽히게. FBX 는 `_bst` 변형 하나(P03 발견 ④)로 `Slime.fbx` · `Bat.fbx` · `Tower.fbx` + `Palette.png`. 렌더(EEVEE) 라인업 1장(로우폴리 3 + 매끈 3 나란히) · 매끈 자세 몇 장을 **열어 보아** 면이 각지지 않고 색이 셀 그대로. 표준 출력 `P04_RESULT` JSON — 모델마다 서브디비전 0 · 1 · 2단계의 삼각형 수 · 정점 수, 내보낸 FBX 크기, 뼈 수, Hop 프레임 13 꼭대기 높이(P03 `extent` 와 같은 방식).
  2. **가져오기**: `Assets/30_Assets/Models/P04_Smooth/` 에 FBX 3 · `Palette.png`. 클립 이름 벗기기(`Rig|` · `.NNN`) · 반복 클립 `loopTime` · 팔레트 텍스처 Point · 밉맵 끔 · 비압축 · Clamp · 노멀은 FBX 의 것(`importNormals = Import`) — `P03ModelImport` 를 폴더 인자로 일반화하거나 `Assets/10_Scripts/Editor/P04/P04ModelImport.cs` 로. 가져온 메시의 삼각형 수 · 뼈 수 · 노멀 수를 스크립트가 출력하고 `P04_RESULT` 와 맞는지 보고에 적는다.
  3. **함정 실측 표**(보고에): (a) 서브디비전을 적용해 내보낸 FBX 에 스킨 가중치 · 뼈가 남는가 — Unity 에서 Hop 프레임 13 의 꼭대기 높이를 로우폴리 판 · `P04_RESULT` 와 대조 (b) 노멀 — 캡처에서 면 경계가 보이지 않고, 메시 노멀이 꼭짓점마다 하나로 이웃 면이 공유되는가(`Mesh.normals` 수 = 정점 수, 수동 재계산 없이) (c) 팔레트 UV — 서브디비전 뒤 셀 경계 번짐이 있는가(근접 캡처 확대) (d) 삼각형 수 — 단계별 수와 로우폴리 대비 배수, 그리고 「2단계 삼각형 수 × 300」(기획서 5절 동시 생존 적 상한 — 숫자만, 판단 없음) (e) Blender 5.x 에서 쓴 스무스 셰이딩 API 이름과 FBX 내보내기 옵션(모디파이어 적용 · 노멀) — 다음 세션이 그대로 쓰게.
  4. **셰이딩 3종**: 머티리얼 `Assets/30_Assets/Materials/PaletteLit.mat`(URP Lit) · `PaletteUnlit.mat`(URP Unlit) · `PaletteCel.mat`(셰이더 `Defense/PaletteCel`, 파일 `Assets/30_Assets/Shaders/PaletteCel.shader` — URP HLSL 로 손으로 쓴 셀: 주 조명 방향에 2~3단 램프 × 팔레트 텍스처 색, 그림자 수신은 되면 넣고 안 되면 빼고 보고). 셋이 같은 `Palette.png` 를 쓴다. 게이트에서 셰이더 컴파일 오류 · 경고 0. 셀 셰이더가 `Assets/Settings/` 렌더러 기능을 요구하면 바꾸지 말고 Lit · Unlit 만으로 진행하고 보고에 이유를 적는다.
  5. **캡처 8**(`z.captures/<날짜>/p04/`, 세로 1080×1920 은 P03 샘플 씬 구도 그대로): 씬 `Assets/00_Scenes/P04_Smooth_Sample.unity`(섬 · 탑 · 슬라임 8 · 박쥐 4 · 세로 카메라 · 조명 — `P03SampleSceneBuilder` 를 모델 경로 · 머티리얼 인자로 일반화하거나 `P04SampleSceneBuilder` 로) 에서 셰이딩 3종 × {매끈 판, 로우폴리 판} = 세로 6장 + 라인업 1장(한 화면에 로우폴리 3 · 매끈 3, Lit) + 근접 1장(슬라임 얼굴, 매끈 Lit). 파일 이름에 판 · 셰이딩이 보이게. 캡처는 `P03FrameRecorder.RenderToPng`(절대 경로)로 — CLI `capture game_view` 는 P03 이 실측했으니 다시 안 해도 된다. 전부 **열어 보아** 매끈함이 보이는지 · 셰이딩 차이가 무엇인지 적는다(판정은 사용자).
