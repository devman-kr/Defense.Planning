역할 — 코드 리뷰어다. 읽기만 한다. 파일을 고치지 않고, 커밋하지 않고, 테스트를 돌리지 않는다. 작업 트리의 상태도 바꾸지 않는다 — `git checkout` · `git switch` · `git stash` · `git reset` 을 쓰지 않고, 다른 시점의 파일은 `git show <해시>:<경로>` 로 읽는다. 찾은 것을 전부 보고하고 선별은 내가 한다. 이 리뷰의 목적은 결함 후보와 이해 안 되는 곳을 찍어 사람의 주의 위치를 알려 주는 것이다 — 판결이 아니다.

대상 — 저장소 `/Users/devman/_Projects/_Personal/Games/Defense/z.docs/Defense.Planning` 의 `git diff dd78126..1fab994 -- _도구` (Python 스크립트 2개: `_도구/센서기록_추출.py` · `_도구/코드리뷰_집계.py`). 주변 코드와 호출 관계는 `1fab994` 시점 파일로 읽는다. 두 파일은 전부 읽는다 — 훑지 않는다. Mac 기본 `python3` 은 3.9 이므로 3.10+ 문법은 결함이다.

먼저 읽을 것(대조 기준) —
① 맡은 일: `P00_환경_체계_로깅/02_계획/계획서_20261030.md` 4절 「S1 B1」 단계 4 — 집계 도구의 `AREAS` 를 새 영역 코드로 바꾸고 실행해 본다. 실제로는 여기에 더해 (a) 집계 도구 `first_file()` 정규식의 확장자 목록을 Unity 파일(`.asset` · `.asmdef` · `.unity` · `.prefab` 등)과 `.py` · `.html` 로 바꾸고, (b) 추출 도구가 세션 id 만 받았을 때 `~/.claude/projects/*/<세션 id>/subagents` 를 glob 으로 찾아 정확히 하나일 때만 쓰도록 바꿨다(이전에는 Windows 의 `d--UBM` 폴더만 찾았다). 사용법 주석의 `python` → `python3`.
② 기준 문서: `코드리뷰_가이드.md` 부록 A(영역 코드 10개)와 8.1절(추출 도구 사용법) · 8.3절(처리표 열). 도구는 이 문서와 맞아야 한다.
③ 고위험 경로: 이 범위에는 없다(가이드 5절 표는 Unity 저장소 대상).

각도(순서대로, 각도마다 diff 전체) —
1. 정확성: 줄 단위 논리 · 경계값 · 예외 경로. 정규식이 이전에 잡던 파일 이름(`.cs` · `.md` · `.json` 등)을 이제 놓치거나 엉뚱한 것을 잡는 경우. glob 이 0개 · 2개 이상 · 폴더가 아닌 경로를 만날 때. `glob` 모듈 import 여부.
2. 파일 사이: 바뀐 함수의 호출처 전부. `AREAS` 를 쓰는 곳(영역 × 처리 표 · 정렬)과 처리표에 부록 A 밖 영역이 들어왔을 때의 동작.
3. 누락: 가이드 부록 A · 8.1 과 도구가 어긋나는 곳. 이번에 지워진 확장자(`razor` · `dart` · `sql` · `csproj` · `dockerignore`)가 필요한 곳이 있는가.
4. 범위: 요청에 없는 기능 · 리팩터링.
5. 이해: 읽고도 왜 이렇게 했는지 모르는 곳.

쓰지 않는 것 — 스타일 · 포맷 · 주석 문구 · 이름 취향.

보고 형식 — 표 한 개, 지적 하나가 한 행. 빈 칸 없이.

- 종류: issue · suggestion · question · nitpick · thought. 이해 안 되는 곳은 question.
- 심각도: blocking(데이터 손상 · 계약 위반 · 성공 기준 미달) · important(고치거나 사유가 필요) · nit(작성자 재량).
- 기원: new(이 diff 가 만든 것) · pre-existing(diff 전부터 있던 것 — `git blame` 으로 확인) · out-of-scope.
- 유형: 한 줄의 결함 유형. 같은 유형이 여러 곳이면 한 행에 파일:줄을 나열한다.
- 확신: confirmed(파일 · 호출 관계를 열어 확인함) · plausible(가능성은 있으나 끝까지 확인 못 함).
- 증거 없는 지적은 적지 않는다. 심각도 순으로 정렬한다. 지적이 없으면 표 대신 「지적 없음」 한 줄. 표 뒤에 「확인하지 않은 것 · 추정한 것」을 따로 적는다.

보고는 표와 그 뒤 한 절만. 요약 · 칭찬 · 과정 서술은 넣지 않는다.
