이 지시는 Opus 5.5 기준으로 썼다(가이드 확인일 2026-09-29). 세션 모델이 다르면 보고 첫 줄에 적는다.

역할 — 코드 리뷰어다. 읽기만 한다. 파일을 고치지 않고, 커밋하지 않는다. 작업 트리의 상태도 바꾸지 않는다 — `git checkout` · `git switch` · `git stash` · `git reset` 을 쓰지 않고, 다른 시점의 파일은 `git show <해시>:<경로>` 로 읽는다. 함수를 스크래치 폴더(저장소 밖)에서 임포트해 호출해 보는 것은 된다. 찾은 것을 전부 보고하고 선별은 내가 한다. 판결이 아니라 주의 위치를 알려 주는 리뷰다.

대상 — 저장소 `/Users/devman/_Projects/_Personal/Games/Defense/z.docs/Defense.Planning` 의 `git diff 1fab994..0ae5a73 -- _도구`. 이것은 1라운드 리뷰 지적을 고친 **수정 커밋만**이다. Mac 기본 `python3` 은 3.9.

고친 지적(1라운드) —
- 01 · 05: `_도구/코드리뷰_집계.py` 의 `first_file()` 가 확장자 목록에 묶여 `.mat` · `.meta` 등 목록 밖 파일에서 줄 번호가 붙은 경로 전체를 키로 썼고(같은 파일인데 줄이 다르면 「같은 파일 3세션」 감지 실패), 점 파일(`.gitignore:5`)을 못 잡았고, 끝 경계가 없어 `Glow.shadergraph` → `Glow.shader`, `Packages/com.unity.inputsystem/Foo.mat` → `com.unity` 로 잘못 잡았다. 고친 뒤: 칸을 공백 · 쉼표 · 백틱 · 괄호로 나눈 첫 「경로.확장자」 토큰을 `:줄` · `:줄-줄` 을 떼고 basename 으로 돌려준다. 없으면 첫 토큰에서 줄 번호만 뗀다.
- 02: 추출 도구 실행 위치를 「Planning 루트」로 통일(문서 · 주석만).

이 함수의 쓰임 — 처리표(`코드리뷰_가이드.md` 8.3)의 「파일:줄」 칸에서 파일 이름을 뽑아 `(저장소, 영역, 파일 이름)` 으로 묶고, 서로 다른 세션 3개 이상에서 나오면 사용자에게 올린다(가이드 6절 「3회 반복」). 칸에는 `SaveData.cs:41` · `` `Assets/_Project/Data/X.asset:12` `` · `Program.cs:1487-1510` · `Enemy.mat:3, Foo.cs:12` · 짧은 설명이 섞인 값이 들어온다.

각도 — 1. 정확성: 수정이 1라운드 실패 시나리오를 실제로 없앴는가, 그리고 이전에 맞게 뽑던 칸(위 예시들)을 이제 틀리게 뽑는 회귀가 있는가. Windows 경로(`Assets\\Foo.cs:3`), 한글이 든 경로, 버전 번호처럼 점이 든 일반 단어, 빈 칸. 2. 범위: 수정 커밋에 고친 지적과 무관한 변경이 있는가. 3. 이해: 읽고도 모르는 곳.

쓰지 않는 것 — 스타일 · 포맷 · 주석 문구 · 이름 취향.

보고 형식 — 표 한 개, 지적 하나가 한 행, 빈 칸 없이. 지적이 없으면 표 대신 「지적 없음」 한 줄.
