# P00 환경 · 체계 · 로깅 검토서

**과제** P00 · **작성** 2026-10-29 · **상태** 검토 완료 — 결정 대기

**이 문서의 위치**: Defense 작업 공간(세 게임 중 첫 번째)을 시작하기 위한 환경 · 관리 체계 · 로깅 · 에셋 파이프라인 · 저장소 호스팅을 한 번에 검토한다. 결정 경위는 [결정기록.md](../결정기록.md), 세 게임 공통 결정은 `_공통/README.md` G-01~G-09. 환경 실측은 3절에 직접 적었다(코드가 없는 과제라 별도 기술근거 없음).

**읽는 사람**: 사용자(결정자 — 1 · 6 · 7 · 8절) · 다음 세션(4 · 7절).

**용어**: 코어 = 세 게임이 공유하는 코드(저장소로는 공유하지 않고 복사, G-07) · 런 = 한 판(10~30분) · 메타 = 런 사이에 남는 성장 · 다이제스트 = 세션 전사를 마크다운으로 줄인 것.

## 1. 결론

Unity 6 로 Defense 를 먼저 만들고, 그 코어를 복사해 AirShooter · RideShooter 를 만든다. 관리 체계는 EasyCheck.Planning 원본을 게임 작업 공간마다 그대로 두었고(골격 완료), 세션 로그는 훅이 토큰 비용 없이 게임별 Logs 저장소에 남긴다(설치 완료, 첫 자동 실행은 다음 세션). 지금 막는 것은 둘이다 — 사용자 미결 4건(`_공통` Q-01~Q-04)과 도구 설치 5건(`_공통` 실행 요청). 답이 오기 전에도 템플릿 Unity 화(B)는 진행할 수 있다.

## 4. 방안

### 4.1 A — 체계 골격 (완료)
EasyCheck.Planning 의 README 구조 · 템플릿 7종 · 가이드 2종 · 도구 2종 · 지표 머리를 복사하고, 세 저장소 전제인 문서에 「사본 메모」를 붙였다(X-01). 루트 `CLAUDE.md` 는 EasyCheck 루트 `CLAUDE.md` 의 절 구성(답변 · 세션 시작 · 우선순위 · 저장소를 가로지를 때 · 푸시 · 공유 자원 · 검색 · 문서 · 프롬프트 작성 · 에이전트 보고 · 코드 리뷰 · 세션 종료)을 그대로 두고 내용만 Unity 작업 공간으로 바꿨다.

### 4.2 B — 템플릿 Unity 화 (예정, 코드 없음, 위험 저)
바꿀 곳: 계획서 1 · 2 · 5절(저장소 하나 · 계약 절은 「코어 공개 API」 · 검증 표의 게이트 = 에디터 컴파일 오류 0 · 콘솔 오류 0 · EditMode/PlayMode 테스트 · 대상 플랫폼 빌드 성공), 작업지시서 「작업 위치」 · 「검증」 · 「금지」(스택 → 에디터 · 빌드), 리뷰어 지시의 경로 · 규칙 불일치 항목, 코드리뷰 가이드 5절 고위험 경로 표(저장 데이터 포맷 · 재화 · 업그레이드 수치 · 빌드 설정 · 패키지 매니페스트 · 서명 · 스토어 설정). Unity 설치 뒤 실제 명령으로 확인하고 쓴다. 끝나면 사본 메모를 지운다.

### 4.3 C — 로깅 훅 (완료)
| 훅 | 스크립트(정본 `_공통/_도구/`) | 산출(`Defense.Logs/`) | 비용 |
|---|---|---|---|
| `UserPromptSubmit` | `log_prompt.py <Logs>` | `prompts/YYYYMMDD.md` 에 시각 · 세션 · 프롬프트 전문 추가 | 토큰 0 · 수 KB/일 |
| `Stop` | `digest_session.py <Logs>` | `sessions/YYYYMMDD_<세션8>.md` 덮어쓰기(턴마다 최신화) | 토큰 0 · 0.1초 |
| `SessionEnd` | 같은 스크립트 + Logs 로컬 커밋 | 위 파일 확정 · 커밋 | 푸시 없음 |

다이제스트에 담는 것: 프롬프트 · 답변 전문, thinking(있는 만큼), 도구 호출(이름 · 핵심 인자), 도구 결과(앞 600자 + 길이), 변경 파일, 실행 명령 목록. 비밀값은 걸러내지 않는다 — 세션이 출력하지 않는 것이 규칙(상위 `CLAUDE.md` 「로깅」).

### 4.4 D — 도구 설치 확인 · `Defense.Unity` 생성 (사용자 실행 뒤)
Unity Hub → Unity 6 최신 LTS(Android · iOS · WebGL 모듈) → 공식 Claude Code 플러그인 → `unity-cli` 로 새 프로젝트(URP · 모바일 템플릿) · 콘솔 읽기 확인 → `Defense.Unity` git 초기화(Force Text · `.gitignore` · `.meta` 커밋 · `ASSETS.md` · `CLAUDE.md` — EasyCheck 저장소 `CLAUDE.md` 의 절 구성을 따르고 Dart 규칙을 C# 으로). Blender → 공식 MCP → 큐브 하나 만들고 glTF 내보내기 확인. gh → 로그인 확인.

### 4.5 E — 레퍼런스 · 에셋 조사 (초안 있음 → 확정)
`_공통/조사/` 의 스타일 보드([추정] 항목)와 무료 에셋 후보(△)를 사용자 캡처와 라이선스 파일로 확정한다. 코어 후보(스폰/웨이브 디렉터 · 체력/피해 · 재화/경험치 · 런 내 업그레이드 드래프트 · 메타 상점 · 저장 · 오브젝트 풀 · HUD/결과/상점 UI · 터치 입력 · 카메라 · 오디오 · 간단 VFX)는 P01 검토서의 입력이다.

### 4.6 F — GitHub (Q-01 · Q-02 뒤)
`_공통` · `Defense.Planning` · `Defense.Logs` · `Defense.Unity` 생성, `main` 보호, 원격 연결, 첫 푸시(허락 뒤). AirShooter · RideShooter 는 그 게임을 열 때.

## 5. 대안 · 외부 의견과의 대조

- Godot: 씬이 텍스트라 에이전트 친화성이 가장 높고 4.6.2 가 Apple Silicon C# 지원. 채용 신호가 약해 기각(G-01).
- 로그 원본(C) 보관: 세션당 7~22 MB, 60세션이면 1 GB. 다이제스트로 대체(G-05).
- Unity AI 생성기: 14일 체험 · 1,000 크레딧, 이후 유료 가능성. 무료 전제에서 제외(G-02).
- 루트 단일 Planning(첫 골격): 사용자 지시로 게임별 분리(G-06). `Common` 패키지 저장소: 저장소 하나 더 · 심사자가 둘을 봐야 해 기각(G-07).

## 8. 위험과 전제

- **일정**: 2026-10-29 부터 12-31 까지 9주. Defense 코어 + 본편 4주, AirShooter 2주, RideShooter 2주, 정리 1주면 여유가 없다. Q-04 의 「게임 수보다 완성도」 원칙이 필요하다. 회사 업무와 병행이면 더 그렇다.
- **3D 모델 품질**: 코드 · Blender 로우폴리는 Supercent 결에 닿을 수 있지만 캐릭터 애니메이션이 약점이다. CC0 애니메이션 팩으로 메우고 직접 제작 비중은 README 에 밝힌다.
- **Unity 플러그인 · `unity-cli` 는 2차 자료로만 확인했다.** 비용 · macOS 동작은 D 에서 확인한다. 안 되면 CoplayDev/unity-mcp(MIT)가 대안이다.
- **코어 복사(G-07)**: 세 번째 게임 때 세 저장소에 같은 결함을 세 번 고치는 비용이 생길 수 있다. 그때 패키지 분리를 H 로 재검토한다.
- **훅은 다음 세션부터 자동이다.** 이 세션은 상위 `Games/` 에서 열려 Defense 훅이 돌지 않았다. 첫 자동 실행 확인이 다음 세션 1번 할 일이다.
- 이 결론은 「세 게임 모두 Unity · 3D · 모바일 · 공개 소스 · 게임별 독립 저장소」 전제 위에 있다. 전제가 바뀌면 P01 코어 설계부터 다시 본다.
