**이 문서의 위치**: 새 과제 P02(문서 프론트매터)를 이 세션(리드)과 서브에이전트로 끝까지 한다. 처음에는 P00 의 새 스트림으로 냈다가, P00 이 종결 절차에 들어가 별도 과제로 옮겼다. 그 뒤 사용자가 P02 를 P00 의 남은 일(작성자 재작성 · GitHub 첫 푸시 · 종결)보다 **먼저** 하기로 정했고, P00 세션(세션 10)은 대기 중이다. 세 게임 · `_공통` 에 걸치는 일이라 첫 게임인 Defense 의 Planning 에 둔다. 방안의 이유는 검토서에 있고 여기서는 되풀이하지 않는다.

## 0. 시작 조건과 다른 세션

- **지금 시작한다.** P00 의 남은 일은 P02 가 끝난 뒤 세션 10 이 잇는다. P02 커밋은 그 뒤의 작성자 재작성(G-16)으로 해시가 바뀐다 — 문서에 적은 P02 해시는 재작성 전 값으로 남는다(G-16 이 받아들인 것).
- **다른 세션 확인** — 저장소에 쓰는 단계마다 직전에 `git status` 와 다른 세션 전사의 수정 시각을 본다. 같은 저장소에서 활동 중이면 멈추고 알린다.
- **로그 저장소** — 어느 세션이든 끝날 때 `digest_session.py` 가 로그 저장소에서 `git add -A` 로 커밋한다. 그래서 로그 이행은 적용과 커밋을 한 번에 하고, 그 사이에 다른 세션을 끝내지 않는다(S3 7번).
- **원격이 아직 없다** — 이 과제의 커밋은 로컬까지다. 첫 푸시는 P00 S5(세션 10)에서 비밀값 검사 0건(G-15) 뒤에 한다.
- **P00 으로 넘길 것**(마감 때 P00 NOTES 에 한 줄) — 다른 두 게임 복사 목록에 규약 · 도구 · 훅 설정, 비밀값 검사 대상에 새 파일.

1. 리드가 지시서 둘을 쓴다 — `20261030_S2a_공통_fm_lint_migrate.md` · `20261030_S2b_공통_로그훅_Planning도구.md`. 먼저 Claude Code 훅 규격(PostToolUse 가 세션에 문제를 돌려주는 방식 — 종료 코드 2 와 표준 오류 또는 JSON 출력 · 입력 필드 `tool_input.file_path`)을 공식 문서로 확인해 B1 지시서에 적는다 [지금은 추정].
2. **B1** — `fm_lint.py`: `python3 -I fm_lint.py [--strict] [--hook] [--json] <경로…>`. 유일성 · 링크 대상의 범위(경로가 속한 게임 작업 공간 + `_공통` + 상위 CLAUDE.md)는 스크립트 위치에서 Games 루트를 찾아 스스로 읽는다. 파서는 평평한 부분 집합, 규칙은 규약 11절 표 그대로. `--hook` 은 표준 입력의 훅 JSON 에서 파일 하나만 보고, 입력을 못 읽거나 범위 밖이면 조용히 0(Clew `block_python_stdin.py`). 본문을 고쳤는데 `updated` 가 오늘보다 이르면 훅에서만 경고. 이어서 `fm_migrate.py`: `draft <게임 폴더> --out <제안.json>`(경로 관례로 doc_type · lifecycle · work_unit, git `--follow` 첫 커밋으로 created, 마지막 커밋으로 updated, git 밖은 파일 생성일, H1 로 title, 로그는 summary 까지, 나머지 id slug · summary · status 는 빈칸) · `apply <제안.json> [--dry-run]`(빈칸이나 린트 오류가 한 행이라도 있으면 아무것도 쓰지 않는다 — Clew `--fill`. 원본 바이트 앞에 블록만, 줄 끝 보존, 임시 파일 → 이름 바꾸기, 쓰기 전후 본문 바이트 대조). `fm_migrate.py` 는 스크립트 폴더를 경로에 넣어 `fm_lint` 를 불러온다(`python3 -I` 는 스크립트 폴더를 경로에 넣지 않는다).
3. **B2** — 로그 훅: `log_prompt.py` 는 새 날짜 파일을 만들 때 프론트매터부터(`{날짜}-prompts` · log · static), `digest_session.py` 는 다이제스트 맨 앞에(`{날짜}-session-{세션8}` · summary = 첫 프롬프트 앞부분과 개수 · 진행 중 draft, SessionEnd 뒤 final). 프론트매터 생성에서 예외가 나도 본문은 쓴다. 로그 스크립트는 `fm_lint` 를 불러오지 않고 작은 쓰기 함수를 각자 두며, 시험이 그 출력을 규약 9절 형식으로 검사한다. Planning 도구: `센서기록_추출.py` 산출물(`agent-*_prompt.md` · `_final.md`)과 `코드리뷰_집계.py --write` 의 `코드리뷰_집계.md` 에 프론트매터(review · register) — 원문 본문은 한 글자도 바꾸지 않는다.

5. **리드 통합** — 시험 전부 다시 돌림 · 로그 훅 정본 교체 뒤 같은 시험을 정본으로 · B2 산출물을 `fm_lint.py` 로 검사 · 세 게임 기준선 린트 수치를 P02 NOTES 에 · 커밋 셋(① 린터 · 이행 스크립트 · 시험 ② 로그 훅 ③ Planning 도구).
