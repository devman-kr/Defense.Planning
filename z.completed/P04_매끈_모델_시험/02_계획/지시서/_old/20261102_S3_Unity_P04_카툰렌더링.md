### 진행 방식 — 사용자가 지켜보는 세션
- **승인 지점 ①~④(아래)에서만 멈춘다.** 멈출 때는 대조 시트 경로 · 확인 페이지 URL 과 함께 선택지를 묻는다 — 선택지는 권장안을 첫째로, 각 선택지에 무엇이 달라지는지 한 줄. 그 밖에는 멈추지 않는다 — 다음 단계를 예고만 하고 턴을 끝내거나, 작업을 막지 않는 결정을 묻거나, 구간이 끝났다고 보고하러 멈추지 않는다.
- **지점마다 전후를 보인다.** 바꾸는 파일과 값(전 → 후), 캡처(전 · 후). 일괄 승인은 없다 — 특히 `Assets/Settings/` 는 바꾸기 전에 바뀔 줄을 보이고 허락을 받은 뒤 저장한다(「승인 지점 ②」).
- 승인이 끝난 단계는 바로 커밋한다(한 지점 = 커밋 1~2, `Assets/Settings/` 변경은 따로 커밋) — 되돌릴 때 지점 단위로.
- 탐구는 웹 검색 · Unity 공식 문서로 한다 — 출처를 기법 표에 적는다. **외부 셰이더 코드를 복사하지 않는다**: 기법을 이해해 직접 쓴다(공개 저장소 · 라이선스 · `ASSETS.md`). 탐구가 한 시간을 넘기면 그 시점까지의 표로 승인 지점 ①을 연다. 커스텀 렌더러 기능 코드를 썼으면 Unity 플러그인 스킬 `unity:validate-urp-render-graph-renderer-feature` 로 검토하고, 볼륨 후처리는 `unity:urp-postprocessing` 을 참고한다(스킬이 없으면 건너뛰고 보고에 적는다).
- 지시는 적힌 대상 전부에 적용한다 — 「5종」은 다섯 모델 모두, 「두 품질」은 Mobile · PC 모두, 「전후」는 둘 다. 더 나은 방법이 보이면 한 문장으로 적고 요청대로 진행한다. 실제로 돌린 검사만 완료로 적는다. 같은 오류를 세 번 넘게 반복하지 않는다.
- 시작 전 한 줄(「지시서와 다른 점」 — 없으면 「없음」)을 사용자에게 알리고 착수한다. 마지막 보고는 그것만 읽어도 되게(「보고 형식」).

### 탐구 범위 — 승인 지점 ①의 기법 표에 전부 넣는다
표의 열: 기법 · 무엇을 하는가 · 실제 게임에서 어디에 쓰이는가(예 1~2 · 출처) · 우리 셰이더에 넣는 법(코드 위치 · 렌더러 변경 필요 여부) · 모바일 비용(패스 · 정점 · 풀스크린 · 텍스처 · 변형) · 권장(켬 · 끔 · 보고 결정) · 근거.
1. **조명 램프**: 단계 램프(지금 — 2~3단 smoothstep) · 램프 텍스처(1D, 스크립트로 생성 — 아티스트가 곡선을 그리는 방식) · 하프 램버트 · 단 경계 폭 · 어두운 단의 채도(어둡게 하며 채도를 올려 탁해지지 않게) · 조명 방향 고정(캐릭터 전용 방향 — 카메라 · 시간대 조명과 무관하게 늘 보기 좋게. 이 게임은 하루 조명이 바뀐다 — 기획서 9절 — 그래서 중요).
2. **그림자**: 받는 그림자의 양자화(감쇠를 단에 묶어 S1 5절의 「바닥 그림자 고리」를 없앤다) · 그림자 색조 · 캐스트 섀도 hard/soft · 해상도 · 캐스케이드 · 바이어스 아티팩트(Mobile 품질 — 소프트 꺼짐 · 1024 · 캐스케이드 1 에서 톱니 · 아크네 · 피터팬) · 발밑 블롭 섀도(쿼드 + 원형 그라데이션 — 모바일 캐주얼의 흔한 대안) · 캐릭터는 자기 그림자를 받지 않고 바닥만 받기.
3. **외곽선** — 적어도 두 방식을 비교한다: (A) 뒤집은 외피(Inverted Hull — 셰이더 안 둘째 패스 `Cull Front`, 법선 방향 확장, 화면 공간 두께 보정, 색 · 두께 속성. 매끈 노멀이라 유리, 정점 처리 두 배) · (B) 후처리 엣지 검출(깊이 · 노멀의 Sobel 또는 Roberts — URP 17 내장 Full Screen Pass Renderer Feature + 풀스크린 셰이더, `_CameraDepthTexture` · `_CameraNormalsTexture`, 화면 두께 일정, 내부선 가능, 풀스크린 비용, 렌더러 변경 필요) · (C) Render Objects 기능의 레이어별 외피(렌더러 변경 필요). 비교 항목: 두께 일관성(원근 · 거리) · 내부선 · 겹침 · 비용 · 설정 변경 필요. 레퍼런스 관찰(S1 보고 5절): XP 히어로 적은 얇은 어두운 외곽선, 피자 레디 · 버거 플리즈는 없음.
4. **림 라이트**(프레넬 단계 — 조명 쪽만 받게) · **스페큘러 하이라이트 단계**(툰 스페큘러) · **주변광**(SH 양자화 · 고정 색).
5. **색 · 후처리**: 볼륨(톤매핑 None · Neutral — 팔레트 원색이 바뀌는지) · 비네트 · 채도. URP 후처리 켜기(카메라 플래그 · 볼륨 프로필 에셋).
6. **그 밖의 실제 게임 기법** — 이 프로젝트에 맞는지 표에 적고 이유를 쓴다(이번에 구현하지는 않는다): 정점 색 AO(Blender 에서 굽기 — `DEF-M03` 후보) · 얼굴 그림자 맵(인간형이 점 눈이라 불필요) · 디더링 페이드 · 머티리얼 하나로 모델 전부(팔레트 유지 원칙과 맞는지).
7. **비용 측정 방법**: 기법마다 드로콜 · 패스 수 · 정점 처리량(외피는 ×2) · 풀스크린 패스 수 · 셰이더 변형 수를 에디터에서 숫자로(`UnityStats` · `ShaderUtil` · `GetPassCountInSubshader`) — 기기 측정은 범위 밖, 「×300」(기획서 5절 동시 생존 적 상한) 환산만.
