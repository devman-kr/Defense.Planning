## 알아 둘 것

- **같은 지시서 · 같은 시작 커밋 · 각자 worktree** 로 두 모델이 따로 했다(D-04). 격리 감사는 Logs 다이제스트로 했고 둘 다 다른 모델의 산출물을 열지 않았다(비교표 2절 7번). 사용자가 (b) 격리 절차(번들 · 삭제)를 건너뛰어 S2 동안 S1 브랜치가 보였지만 접근 흔적은 없다.
- 한 기기(G-01) — Blender 와 Unity 에디터를 같이 띄우지 않는다. 두 세션 모두 Blender → 에디터 → 끄기 → Blender(MP4) 순서를 지켰다.
- `bpy` 스크립트는 `Defense.Unity/Tools/Blender/`(그 폴더만 GPL-3.0-or-later, G-17 · D-09). 결함 둘은 S2 가 고쳤고(날개 UV 층 이름), 「날갯짓 회전축」은 두 모델이 독립적으로 원근 착시로 판정했다.
- Supercent 스타일은 추정이다(`_공통/조사/Supercent_스타일보드.md` 3절 [추정]). 레퍼런스 캡처(실행 요청 5)는 아직 없다.
- 기획서 9절은 적 모델을 Quaternius(CC0) 1순위로 적었다 — 샘플이 저장소에 들어갔지만(D-02) 본편에 쓸지는 `DEF-M03` 에서 D-nn → 기획서.
- `Defense.Unity` 폴더 체계가 `_Project/` 에서 번호 폴더로 바뀌었다(D-09, 2026-10-31) — 다른 두 게임의 P00 복사 목록(`Unity_CLAUDE.md` · 코딩 표준 · `Unity_README.md` 템플릿)도 새 판을 쓴다.
