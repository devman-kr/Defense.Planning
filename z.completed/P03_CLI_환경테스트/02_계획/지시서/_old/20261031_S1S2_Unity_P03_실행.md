## 프롬프트 본문 (여기부터 붙여 넣는다)

이 지시서는 **Sonnet 5.5 와 Opus 5.5 두 모델에 같은 본문**으로 썼다(프롬프트 작성 가이드 확인일 2026-09-29). 세션 모델이 둘 중 하나가 아니면 시작 전에 사용자에게 알린다. 아래에서 `<모델>` 은 자기 모델 계열 이름을 소문자로 — `sonnet` 또는 `opus` — 폴더 · 브랜치 이름에 쓴다.

### 맡는 일
- 과제 `P03`(CLI 환경 시험) · 세션 `S1`(Sonnet) 또는 `S2`(Opus) · 스트림 실행 · 마일스톤 없음(저장소 제품 코드를 바꾸지 않는 시험).
- Blender 를 창 없이 돌려 샘플 적 캐릭터 둘(슬라임 · 박쥐)과 등불 탑을 만들고, Unity 샘플 씬에 놓아 CLI 로 정지 캡처와 2초 녹화를 만든다. 끝나면 사용자가 그림 · 동영상으로 「Blender CLI → FBX → Unity CLI → 캡처」가 이 Mac 에서 끝까지 도는 것을 확인할 수 있고, 파이프라인의 함정 둘(클립 이름 · 루트 회전)의 실측값이 작업 보고에 남는다. 이 결과는 다음 아트 마일스톤(`DEF-M03`)이 파이프라인을 정할 때의 근거가 된다.
- 이 일은 **두 모델이 같은 조건으로 따로 하는 비교 실험의 한쪽**이다. 다른 쪽의 결과 · 브랜치 · 폴더를 보지 않는다(「금지」). 시간이 재어지므로 사용자를 기다리는 멈춤을 만들지 않는다(「진행 방식」).

### 진행 방식
- 사용자는 세션을 지켜보지 않는다. 요청한 것이 끝날 때까지 계속하고, 「금지」 · 「계약」에 걸리는 일이나 사용자 없이는 못 나아가는 일 앞에서만 멈춘다. 다음 단계를 예고만 하고 턴을 끝내거나, 작업을 막지 않는 결정을 묻거나, 한 구간이 끝났다고 보고하러 멈추지 않는다 — 구간 결과는 작업 보고에 쓴다.
- 지시는 적힌 대상 전부에 적용한다 — 「모델 3종」이면 슬라임 · 박쥐 · 탑 모두, 「두 변형」이면 `*.fbx` · `*_bst.fbx` 모두.
- 더 나은 방법이 보이면 보고에 한 문장으로 적고, 요청대로 진행한다. 요청하지 않은 기능 · 테스트 · 파일 · 문서 · 리팩터링은 하지 말고 끝에 제안으로 적는다.
- 실행 · 컴파일 · 테스트를 돌릴 수 있는 변경은 실제로 그 변경을 거치는 검사를 돌린 뒤 완료로 적는다 — 구문 검사 · 파일 존재만으로는 부족하다. 못 돌렸으면 무엇을 왜 못 돌렸는지 적는다.
- 시작 전 한 줄(「지시서와 다른 점」 — 없으면 「없음」)을 사용자에게 알리고 바로 착수한다. 작업 중 사용자에게 쓰는 글은 짧게, 마지막 보고는 그것만 읽어도 되게(「보고 형식」).

### 성공 기준 · 위험 · 되돌리는 법
- **성공 기준**(확인 방법을 붙였다 — 리뷰 센서는 이 조건에 대조한다):
  1. **Blender 다듬기**: `Tools/Blender/make_enemies.py` 를 고쳐 `Blender -b --factory-startup -noaudio --python-exit-code 1 --python Tools/Blender/make_enemies.py -- <출력 폴더>` 가 종료 0 이고, 렌더 PNG 를 **열어 보아** 박쥐 날개가 팔레트 셀 6(어두운 보라)이며 날갯짓(`render_bat_Flap_f01.png` 위 · `_f06.png` 아래)이 몸을 축으로 위아래로 움직인다. 슬라임 · 탑은 지금 렌더(`z.captures/20261031/render_*.png` — 읽기 허용)와 같아야 한다. 표준 출력의 `P03_RESULT` JSON 을 보고에 붙인다.
  2. **가져오기**: `slime.fbx` · `bat.fbx` · `tower.fbx` 와 `_bst` 변형 셋, `palette.png` 이 `Assets/30_Assets/Models/P03_CLI/` 에 있고, 씬에 쓰는 변형의 클립이 **뼈대 접두 없이** `Idle` · `Hop` · `Hit` · `Die`(슬라임) · `Flap` · `Hit`(박쥐)으로 보인다 — `ModelImporter.clipAnimations` 를 코드로 설정하고 `asset get_import_settings` 또는 스크립트 출력으로 확인. 반복 재생할 클립(Idle · Hop · Flap)은 `loopTime` 을 켠다.
  3. **함정 둘 실측값 표**(보고에): (a) 가져온 직후 클립 이름(벗기기 전 — 모델 셋) (b) 두 변형의 루트 오브젝트 회전 · 스케일과 뼈 수 (c) 씬에 어느 변형을 썼고 왜.
  4. **샘플 씬** `Assets/00_Scenes/P03_CLI_Sample.unity`: 잔디 원판 섬(프리미티브 · 초록) · 중앙 등불 탑 · 탑을 보는 슬라임 8(반지름 3~5 m 원 위) · 높이 1.5 m 안팎의 박쥐 4 · 세로 9:16 원근 카메라(탑다운 사선) · 방향광 + 등불 자리 점광. 머티리얼은 URP Lit(또는 Simple Lit) 하나에 팔레트 텍스처(Point 필터)를 공유. `scene get_hierarchy` 결과 요약(오브젝트 수 · 이름)을 보고에.
  5. **정지 캡처 2**: `z.captures/<날짜>/<모델>/capture_portrait_1080x1920.png` · `capture_landscape_1920x1080.png` — CLI `capture game_view --source camera` 로. 창 없는 에디터에서 이 명령이 그림을 내지 못하면(검은 화면 · 오류) 에디터 스크립트의 카메라 → RenderTexture → PNG 로 대체하고, 어느 쪽이 됐는지 · 오류 원문을 보고에 적는다. 캡처를 **열어 보아** 섬 · 탑 · 슬라임 · 박쥐가 보여야 한다.
  6. **녹화**: 48프레임(24 fps · 2초 — 클립을 시간으로 샘플링(`AnimationClip.SampleAnimation` 또는 Animator 없이 같은 효과), 슬라임은 Idle · Hop 을 섞고 개체마다 위상을 다르게, 박쥐는 Flap) PNG → 에디터를 끈 뒤 Blender 내장 ffmpeg(VSE 이미지 스트립 → `FFMPEG` · `MPEG4` · `H264`)로 `z.captures/<날짜>/<모델>/sample_48f_24fps.mp4`. Blender 로 그 MP4 를 다시 읽어 프레임 수 48 을 확인한다.
  7. **게이트 · 보고 · 센서 · 커밋**: 「검증」대로 통과하고 worktree 브랜치에 커밋 2 이상(Blender 산출 / Unity 쪽) + 보고 · 센서 기록 커밋. 「산출물」의 세 가지가 모두 있다.
  8. **확인 페이지**: claude.ai 비공개 페이지 하나 — 렌더 · 캡처 2 · 동영상(또는 프레임 몇 장) · 함정 둘 표 · 쓴 명령과 걸린 시간. URL 을 보고에.
- **위험 등급**: 저 — 에디터 전용 스크립트(asmdef `includePlatforms: Editor`) · 시험 씬 · 샘플 에셋 · `Tools/Blender/` 스크립트. 제품 런타임 코드 · 고위험 경로(`ProjectSettings/` · `Packages/` · 저장 · 재화) 변경 없음. **폭발 반경**: 이 브랜치의 새 파일과 `z.captures/<날짜>/<모델>/` 뿐.
- **되돌리는 법**: 브랜치 삭제로 끝난다(저장 포맷 · 빌드 · 게시 없음).
