# 비교표 — P03 S1(Sonnet 5.5) · S2(Opus 5.5) 실행 브랜치 판정

**이 문서의 위치**: [지시서 S3](../02_계획/지시서/_old/20261031_S3_판정.md) 의 산출물. 두 실행 세션이 같은 [지시서 S1·S2](../02_계획/지시서/_old/20261031_S1S2_Unity_P03_실행.md) 로 시작 커밋 `763866b` 에서 만든 브랜치 `p03/exec-sonnet`(머리 `e2e5061`, 커밋 6) · `p03/exec-opus`(머리 `9250f22`, 커밋 4)를 판정 세션(Fable 5.1, 세션 a3a90bb0, 2026-11-01)이 **산출물로 검산**한 결과다. 보고의 주장을 그대로 옮긴 곳은 △, 직접 확인한 곳은 ✔. 결정은 [결정기록](../결정기록.md) D-11.

**읽는 사람**: 사용자(1절 · 2절 · 캡처 그림) · 다음 아트 마일스톤 `DEF-M03`(5절 발견).

## 1. 결론

- 두 브랜치 모두 성공 기준 8개를 채웠고, 닫힘 게이트를 통과했으며, 함정 둘의 실측값이 서로 같고 Blender 값과 맞는다. 둘 다 머지해도 되는 품질이다.
- 차이는 넷이다. ① **Opus 는 시간 43분 · 새 토큰 108만**, Sonnet 은 **88분 · 242만**(각각 메인 + 리뷰 에이전트). ② Opus 는 성공 기준 4 「머티리얼 하나」를 섬까지 지켰고(센서 지적 뒤), Sonnet 은 섬에 단색 머티리얼을 따로 두고 「모델에 대한 말」로 읽었다. ③ Sonnet 은 프레임 녹화에서 **박쥐 날개가 움직이지 않는 결함**을 센서 반론으로 찾아 고쳤다(`forceMatrixRecalculationPerRender`) — Opus 의 녹화는 같은 방식인데 날개가 움직였고 원인 차이는 확인하지 못했다. ④ Sonnet 의 세로 캡처 구도가 화면을 더 채운다(섬 큼 · 박쥐가 바깥 고리), Opus 는 박쥐가 슬라임 고리 안쪽이라 겹쳐 보이는 자리가 있다.
- **판정 세션의 권고는 `p03/exec-opus` 머지**다 — 기준을 더 글자대로 지켰고, 코드가 작고(3파일 420줄 · 8파일 660줄), 시간 · 토큰이 절반이며, `DEF-M03` 에 넘길 CLI 발견이 더 구체적이다. Sonnet 이 찾은 스킨 행렬 함정은 머지와 무관하게 5절로 가져간다. 최종 선택은 사용자(D-05).

## 5. 두 보고가 `DEF-M03` 에 넘긴 발견 (합집합 — P01 NOTES 4번으로)

- **CLI 캡처**: `capture game_view --source camera` 는 창 없는 에디터(`-batchmode`, `-nographics` 없음)에서 그림을 낸다 — 1080×1920 한 장 0.2~0.3초. `--save_path` 는 `Assets/` 기준이라 프로젝트 밖 · `..` 는 거부(`outside the project root` · `must not contain '..'`), `Temp/` 를 줘도 `Assets/Temp/` 에 떨어져 가져와진다 → 찍고 옮긴 뒤 `AssetDatabase.DeleteAsset`. 대체 경로(카메라 → RenderTexture → PNG)는 절대 경로가 된다(두 세션 모두 프레임에 씀). 둘 다 확인.
- **에디터 기동**: 클론한 `Library/` 로 바로 열림 12~15초, 둘째 기동 6초. 키체인 대화상자 없음. 가져오기 7파일 0.5초 · 씬 빌드 0.6초 · 프레임 48장 1.5~2초 · 닫힘 게이트 6~7초. 둘 다 확인.
- **스킨 메시 녹화(Sonnet)**: 한 에디터 프레임 안에서 `SampleAnimation` → `Camera.Render` 를 되풀이하면 자식 뼈 회전이 첫 포즈에 머물 수 있다 — `SkinnedMeshRenderer.forceMatrixRecalculationPerRender = true` 로 해결(실측 박쥐 경계 상자 y 1~2 px → 11~26 px). Opus 의 같은 방식 녹화에서는 재현되지 않았고 원인 차이는 미확인 — `DEF-M03` 녹화 도구는 이 플래그를 기본으로 켠다.
- **Blender**: `from_pydata` 메시는 `join` 전에 `uv_layers.new(name="UVMap")`(bmesh 가 만드는 층은 `Float2`). 동작 이름은 파일 전체에서 하나라 같은 이름이 `.001` 로 나간다(`BatRig|Hit.001`) — 가져오기 코드가 꼬리를 벗기거나 모델마다 이름을 다르게. VSE MP4 는 `media_type = 'VIDEO'` 를 먼저, `view_transform = 'Standard'`. `Material.use_nodes` · `World.use_nodes` 는 6.0 에서 제거 예정. 둘 다 확인.
- **`bake_space_transform`**: 뼈대 오브젝트의 X 270° 는 없애지 않는다. 정적 모델은 `_bst` 가 루트 0°(기본 변형 탑 루트 270.0198°), 스킨 모델은 굽힘이 같다 → 기본안 `_bst` 하나만. Blender 설명문의 「experimental · armature 와 함께 깨질 수 있음」 경고는 이 리그(뼈 2~3)에서 안 나타났다 — 뼈 많은 리그에서 `bakeAxisConversion` 과 다시 비교. 둘 다 확인.
- **팔레트**: Point · 밉맵 끔 · 비압축 · Clamp. 프리미티브에 팔레트를 쓰려면 UV 를 셀 중심으로 모은 메시 사본이 필요(Opus `island.asset`) — 파이프라인 단계가 된다. FBX 머티리얼은 `AddRemap(Palette → palette.mat)` 으로 공유.
- **`EditorSceneManager.NewScene`** 이 `ProjectSettings/SceneTemplateSettings.json` 을 만든다(두 세션 모두 지움) — `DEF-M01` 이 커밋 · `.gitignore` 를 정한다.
- 이름 · 규칙: asmdef `Defense.Editor` 가 `UnityEditor.Editor` 를 가린다(`class X : Editor` 가 CS0118) · 에디터 스크립트 이름 `*Builder*` 가 고위험 패턴 `Editor/*Build*` 에 걸릴 수 있다 · Blender 출력 소문자(`slime.fbx`)와 §17 PascalCase 가 다르다 · 씬을 빌더로 통째로 다시 만들면 fileID 가 바뀌어 diff 를 읽을 수 없다 · macOS `core.ignorecase` 에서 대소문자만 바꾼 이름은 `git rm --cached` 뒤 `add`.
