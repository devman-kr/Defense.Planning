# 작업지시서 — Pnn · 세션 n · 제목(스트림 글자)

병렬 에이전트(Ultracode · Agent Teams)에 넘기는 프롬프트의 골격이다. 작성한 지시서는 `02_계획/지시서/YYYYMMDD_Sn_제목.md` 로 저장하고(YYYYMMDD = 작성일 · Sn = 계획서 분할표의 세션 번호 `S1` · `S3a` · `S4b` · 제목 = 저장소 · 마일스톤 · 일 — 예 `20261105_S4_Unity_DEF-M01.md`. 계획 밖 임시 지시서(조사 위임 · 점검)는 세션 번호 없이 `YYYYMMDD_제목.md`. 실행한 지시서는 이름을 바꾸지 않는다), 프롬프트 본문에 그대로 붙인다. 수행이 끝나면 그 세션의 종료 절차에서 `02_계획/지시서/_old/` 로 옮긴다(루트 `CLAUDE.md` 「세션 종료」 7번). 지시서 없이 넘긴 작업은 재실행도 사후 확인도 어렵다. 문장 쓰는 법과 받는 모델에 따른 조정은 [`../프롬프트_작성_가이드.md`](../프롬프트_작성_가이드.md). 「성공 기준 · 위험 · 되돌리는 법」 · 「승인 지점」 · 「검증」의 리뷰 문장은 [`../코드리뷰_가이드.md`](../코드리뷰_가이드.md) 2 · 5절을 따른다.

### 성공 기준 · 위험 · 되돌리는 법
- **성공 기준**: 끝났다고 말할 수 있는 조건을 확인 가능한 문장으로 3~7개. 각 조건에 확인 방법(명령 · 화면 · 응답 키)을 붙인다. 리뷰 센서는 이 조건에 대조한다 — 코드에 대응이 없는 조건은 지적이 된다.
- **위험 등급**: 저 · 중 · 고 가운데 하나와 이유(`../코드리뷰_가이드.md` 5절 — 변경이 정한다. 고위험 경로 · 저장 포맷 · 빌드 설정 · 패키지 · 서명 · 되돌릴 수 없는 변경 · 기획 데이터 표 ↔ 데이터 에셋 계약 변경이면 고). **폭발 반경**: 영향 화면 · 기존 저장 파일 · 대상 플랫폼.
- **되돌리는 법**: `git revert` 로 끝나는가 · 저장 포맷을 올렸으면 이전 버전 저장 파일을 읽을 수 있는가 · 게시한 빌드(WebGL · APK)는 `z.builds/` 의 이전 빌드를 다시 올린다. 되돌릴 수 없는 단계가 있으면 그 직전을 「승인 지점」에 넣는다.

### 승인 지점
- 지시서가 미리 정하지 않은 것 가운데 사용자 승인이 필요한 행동만 적는다 — 패키지 추가(`Packages/manifest.json`) · `ProjectSettings/` · 플랫폼 전환 · 빌드 설정 · 에디터 재시작 · 서명 자료 · 비밀값 · 배포 워크플로 · 되돌릴 수 없는 행동. 「없음」이면 그렇게 적는다.
- 위험 등급이 **저**면 구현 세션은 계획을 「지시서와 다른 점」 한 줄로 알리고 바로 착수한다. **중 · 고**는 저장소 `CLAUDE.md` 대로 계획 제시 후 승인을 기다린다(저장소 `CLAUDE.md` 「작업 시작 전」 위임 줄).
