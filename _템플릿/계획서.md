## 2. 계약 — 기획 데이터 표 ↔ Unity 데이터 에셋

이 게임에서 저장소 사이의 계약은 기획 저장소의 **데이터 표**와 Unity 저장소의 **데이터 에셋(ScriptableObject)** 사이에 있다. 표의 열이 에셋 필드가 된다. 같은 Unity 저장소 안에서는 **코어 공개 API**(`Assets/_Project/Core/` 의 public 타입 · 메서드 — 다른 게임이 복사해 간다, G-07)가 세션 사이의 계약이다. **계약이 확정되기 전에는 그 데이터 · API 를 쓰는 코드를 병렬로 돌리지 않는다**(루트 `CLAUDE.md` — 코드가 기획서보다 앞서가지 않는다).

| # | 계약 | 기획 쪽(`Defense.Design/데이터/`) 또는 코어 API | Unity 쪽 | 바뀌는 것 | 상태 |
|---|---|---|---|---|---|
| K1 | | `<표>.md` 의 열 | `<이름>Def` 필드 | 신설 / 열 추가 / 의미 변경 / 폐기 | 초안 / 확정 / 커밋(해시) |

- 기획 쪽을 먼저 고치고 커밋한 뒤 Unity 쪽을 고친다. 수치 변경은 데이터 에셋만 — 코드 상수로 넣지 않는다(저장소 `CLAUDE.md` 「코딩」).
- 재화 · 영구 강화 · 해금 · 저장 포맷이 걸린 계약은 고위험, 그 밖의 밸런스 수치는 중(`../코드리뷰_가이드.md` 5절).

## 3. 순서와 의존

```
S1 ─┐
    ├─ S3(계약 K1 확정 후 S4a · S4b 병렬)
S2 ─┘
```

| 순서 | 작업 | 저장소 | 의존 | 규모 | 위험 등급 | 병렬 가능 |
|---|---|---|---|---|---|---|
| 1 | | | | | 저 · 중 · 고 | |

- **분리 규칙**: `ProjectSettings/` · `Packages/manifest.json` · 빌드 설정 · 저장 포맷 변경은 기능 변경과 **따로 커밋**한다 — 되돌릴 때 기능을 함께 잃지 않게. 세션 하나는 리뷰 가능한 크기(코드 50파일 · 5,000줄 안 — 씬 · 프리팹 · `.meta` 제외)로 자른다. 넘으면 세션을 나누거나 지시서에 센서 영역 표를 둔다(`../코드리뷰_가이드.md` 2절).

## 4. 분할표 (병렬 실행용)

세션(에이전트) 하나 = 한 행 — 행 번호 `S1` · `S2` · `S3a` 가 지시서 파일 이름의 `Sn` 이 된다. **저장소 단위 분할이 기본.** 같은 Unity 프로젝트를 나누면 asmdef 폴더 단위로 파일 영역이 겹치지 않아야 하고, **씬 · 프리팹 · `.asset` 은 한 세션만** 만진다(YAML 충돌은 사람이 못 푼다). 지시서는 `지시서/YYYYMMDD_Sn_제목.md` 로 남긴다(`../_템플릿/작업지시서.md`).

| 세션 | 저장소 · 브랜치(worktree) | 파일 영역(수정 허용) | 읽기 전용 | 산출물 | 검증 방법 | 금지 |
|---|---|---|---|---|---|---|
| S1 | Unity · `pnn/s1-slug` | `Assets/_Project/Core/<영역>/` · `Assets/_Project/Tests/EditMode/<영역>/` | 기획서 · 데이터 표 · 씬 · 프리팹 | 커밋 + 작업 보고 | 저장소 `CLAUDE.md` 「결정론 게이트」 통과 | 에디터 조작 · 빌드 · 패키지 추가 |

오케스트레이터(주 세션)만: 열린 Unity 에디터 · 플레이 모드 · 빌드 · 플랫폼 전환 · Blender · 실기기 · 머지(루트 `CLAUDE.md` 「공유 자원」). 서브에이전트는 코드 · 컴파일 · EditMode 테스트까지.

## 5. 검증

게이트 명령은 `Defense.Unity/CLAUDE.md` 「결정론 게이트」 한 곳에만 있다 — 여기에는 단계와 통과 기준만 적는다.

| 단계 | 저장소 | 방법 | 통과 기준 |
|---|---|---|---|
| 컴파일 | Unity | 저장소 `CLAUDE.md` 「결정론 게이트」 | 컴파일 오류 0 · 새 경고 0 |
| EditMode | Unity | 같음 | 베이스라인 대비 실패 증가 0 |
| PlayMode 스모크 | Unity | 같음 — 런 흐름을 바꿨으면(자동 선택 + 가속 한 판) | 통과 |
| 대상 빌드 | Unity | 같음 — 빌드 설정 · 플랫폼 · 패키지를 바꿨으면(Android · WebGL) | 빌드 성공 · `z.builds/BUILDS.md` 한 행 |
| 계약 | Design ↔ Unity | 데이터 표의 열 ↔ 데이터 에셋 필드 · 값 대조 | 불일치 0 |
| 플레이검사 | Unity | `Defense.Design/플레이검사_체크리스트.md` 의 이 마일스톤 항목. 수치는 빌드 · 기기 · 날짜와 함께 | 체크리스트 통과 기준 · 결과는 `03_작업기록/플레이검사_<날짜>_<세션>/` |
| 세션 센서 | 코드를 고친 저장소 | 구현 세션 끝 `<시작 해시>..HEAD` 에 읽기 전용 리뷰어 1(`../_템플릿/리뷰어_지시.md` A). 위험 등급 고인 세션은 고위험 센서(A + B + 검증 C). 「틀림 · 의도」는 판정 반론 D. 2라운드는 수정 커밋만 한 번(`../코드리뷰_가이드.md` 2 · 3 · 6절). 산출 = 과제 폴더 `03_작업기록/코드리뷰_<날짜>_<세션>/`(원본 · `처리.md` — 가이드 8절) | `blocking` 0 · `important` 전부 고침 또는 사유 · 미해결은 사용자 판정 |
| 마일스톤 리뷰 | 기능 브랜치가 있는 저장소 | 통합 · 머지 세션 맨 앞, `<분기점>..<브랜치>` 에서 **세션 사이 어긋남 · 고위험 경로만**(가이드 2절 ④). 세션 센서를 반복하지 않는다. 범위(코드 파일 · 줄)와 고위험 경로 파일 목록을 여기 적는다 — 세션 센서를 건너뛴 세션이 있으면 그 범위를 먼저 메운다 | 같음 |
| 지표 | Planning | 과제 종결 때 `python3 -X utf8 -I _도구/코드리뷰_집계.py --task Pnn` 으로 초안 → [`../지표.md`](../지표.md) 한 행 + 원천 수정 루프 한 줄, `--write` 로 `코드리뷰_집계.md` 덮어쓰기(가이드 7 · 10절) | 행이 있다 |

- 한 기기(G-01): Unity 에디터 · Blender · 로컬 이미지 생성을 같이 띄우지 않는다. 이 과제에서 무엇을 언제 여는지.

- 측정 기기 · 빌드(성능 · 플레이 시간 수치를 적을 때).
