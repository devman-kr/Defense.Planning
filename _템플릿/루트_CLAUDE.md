# Defense 작업 공간

이 폴더(`~/_Projects/_Personal/Games/Defense`)는 git 저장소가 아니라 **작업 공간**이다 — EasyCheck 작업 공간(`~/UBM`)과 같은 배치다. 안에 독립 git 저장소가 있다 — `Defense.Unity`(Unity 6 프로젝트, 공개 포트폴리오 저장소 — Unity 설치 뒤 생성) · `z.docs/Defense.Planning`(과제 관리 — 마일스톤 단위 작업 계획) · `z.docs/Defense.Design`(기획 문서, G-10) · `z.docs/Defense.Logs`(세션 로그 — 훅이 쓴다). 이 문서의 정본은 `z.docs/Defense.Planning/_템플릿/루트_CLAUDE.md` 이고 여기는 사본이다 — 고칠 때는 정본을 고치고 복사한다(X-01). 세 게임에 공통인 규칙은 상위 `../CLAUDE.md`(G-nn 은 `../_공통/README.md`). git 밖 설정은 이 Mac 에만 있다 — `.claude/settings.json`(로깅 훅 · 권한) · `.mcp.json`(GitHub MCP, 토큰은 환경 변수 `GITHUB_PAT`). 사본 · 설명은 Planning `P00_환경_체계_로깅/NOTES.md` 「현재 상태」.

게임 기획 · 특징(규칙 · 재화 · 화면 흐름 · 아트 · 범위 · 제목)은 전부 `z.docs/Defense.Design/` 에서 정리한다 — 정본 `기획서.md`(G-10). 이 문서에는 적지 않는다. 기획과 다른 지시를 받으면 Planning 과제 `결정기록.md` 에 D-nn 을 남기고 기획서를 고친 뒤 구현한다 — 코드가 기획서보다 앞서가지 않는다.

## 답변
- 모든 최종 답변은 한글로 대답한다. 사용자에게 보이는 글은 전부 한글 — 진행 메시지, 질문(선택지 포함), 보고, 세션 끝 요약. 코드 · 명령 · 파일 경로 · 식별자는 원문 그대로 둔다.

## 세션 시작
1. `z.docs/Defense.Planning/README.md` 현황판과 `NOTES.md` 「다음 세션 시작 전 확인」을 읽는다.
2. 작업할 과제의 `NOTES.md` 같은 절을 읽는다.
3. **저장소를 건드리기 전에 그 저장소의 `CLAUDE.md` 를 읽는다.** 루트에서 세션을 열면 자동으로 읽히지 않는다. Planning · Design · Logs 에는 `CLAUDE.md` 가 없다 — 규칙은 각 `README.md`.
4. 손댈 저장소마다 `git pull --ff-only`. 빨리감기가 안 되면 멈추고 원인을 알린다.

## 우선순위
- 저장소 안 작업(코드 · 문서 · 커밋)은 **그 저장소 `CLAUDE.md`** 를 따른다 — 계획 제시 후 승인, 작업 보고서, `verb: 한글 제목` 커밋과 트레일러, 코드 컨벤션, 테스트 규율.
- 저장소를 가로지르는 일(검토 · 결정 · 계획 · 인계)은 `z.docs/Defense.Planning/README.md` 를 따른다.
- 둘이 충돌하면 저장소 `CLAUDE.md` 가 우선한다. 충돌을 발견하면 Planning `NOTES.md` 「함정」에 적고 사용자에게 알린다.

## 저장소를 가로지를 때
- **커밋은 저장소별로 따로.** 제목에 과제 태그 — `modify: [P01] 웨이브 디렉터 난이도 곡선`. 세션 끝에 과제 `03_작업기록/작업색인.md` 에 저장소별 커밋을 한 표로 남긴다.
- **마일스톤은 저장소 접두로 지칭한다**: `DEF-M01`(Unity 저장소). 다른 게임의 코어를 복사해 왔으면 README 「출처」에 원본 저장소 · 커밋을 적는다(G-07).
- 저장소 간 협의 문서(handoff)는 만들지 않는다. 한 에이전트가 양쪽을 고친다.

## 푸시
- 푸시는 **사용자가 허락한 뒤에만** 주 세션이 한다. 허락 없이 먼저 푸시하지 않는다. 서브에이전트는 푸시하지 않는다.
- 작업을 마치고 커밋까지 끝나면 **푸시해도 되는지 사용자에게 묻는다.** 질문에 저장소 · 브랜치 · 올릴 커밋(해시와 제목) · 태그 포함 여부를 적는다. 손댄 저장소가 여럿이면 저장소별로 나열해 한 번에 묻는다.
- 허락은 **질문에 적은 저장소 · 브랜치 · 커밋까지**다. 다음 작업의 푸시로 이어지지 않는다. 푸시한 뒤에는 올라간 커밋과 `git status` 로 확인한 결과를 보고한다.
- 이 허락에 강제 푸시 · 훅 우회 · 태그 삭제 · 원격 브랜치 삭제는 들어 있지 않다. 푸시가 인증 · 거부로 실패하면 재시도하거나 우회하지 않고 오류를 그대로 알린다.
- **GitHub MCP · `gh` 로 원격에 쓰는 일은 푸시와 같다** — 저장소 생성 · 파일 생성/수정/삭제 · 브랜치 · PR · 머지 · 이슈 · 댓글 · 워크플로 실행. 같은 질문 · 같은 허락 범위를 거친다(`.claude/settings.json` `permissions.ask` 가 MCP 쓰기 도구를 막아 둔다). 읽기(저장소 · 이슈 · Actions 결과 조회)는 묻지 않는다. 코드는 MCP 의 파일 쓰기가 아니라 로컬 커밋 → `git push` 로 올린다. 토큰 값은 출력하지 않는다(`gh auth token` 결과를 화면에 찍지 않는다).
- Logs 저장소의 훅 커밋도 로컬까지다. 푸시는 같은 규칙.

## 공유 자원 — Unity 에디터 · 기기
- **Unity 에디터는 사용자가 연다.** 세션은 열린 에디터를 `unity-cli`(Unity 공식 Claude Code 플러그인)로 다룬다 — 씬 · GameObject · 프리팹 · 컴포넌트 값 · 콘솔 · 빌드. 에디터 재시작 · 패키지 설치 · 프로젝트 설정 · 플랫폼 전환 · 빌드 설정 변경은 **승인 지점**이다.
- 씬 · 프리팹 · 에셋(`.unity` · `.prefab` · `.asset`)은 텍스트 직렬화(Force Text)로 두고 손으로 YAML 을 고치지 않는다 — 에디터로 바꾸고 저장한 뒤 `git status` 로 확인한다. `.meta` 는 반드시 커밋한다.
- `Library/` · `Temp/` · `Logs/` · `obj/` · `Builds/` · `UserSettings/` 는 커밋하지 않는다. 빌드 산출물(APK · AAB · IPA · WebGL)은 작업 공간 `z.builds/` 에 둔다(규칙 `z.builds/README.md`). 서명 자료는 git 에 넣지 않는다.
- 실기기 설치 · 플레이는 사용자 실행 요청. 세션은 에디터 플레이 모드 · 시뮬레이터 · WebGL 로컬 서버까지 한다.
- 서브에이전트에는 코드 · 컴파일 · 테스트까지 맡긴다. 에디터 조작 · 빌드는 주 세션만.

## 검색 · 문서
- **화면 캡처는 바탕화면에 두지 않는다.** 프로젝트용 캡처(⌘⇧3 · ⌘⇧4 · 시뮬레이터 ⌘S · 기기 캡처 · 에디터 게임 뷰)는 세션이 바로 작업 공간 `z.captures/<YYYYMMDD>/`(git 밖)로 옮기고(`mv -n` 뒤 SHA-256 대조), 날짜 폴더 `README.md` 에 원본 · 내용 · git 사본을 적는다. 문서에 쓰는 것은 그 저장소 `assets/` 에 사본을 넣되, 넣기 전에 열어 보고 비밀값과 다른 앱 · 다른 대화 정보를 잘라내거나 가린다. 규칙 `z.captures/README.md`.
- 검색 · 집계에서 `Defense.Unity/Library` · `Temp` · `Logs` · `obj` · `Builds` 와 `z.docs/Defense.Logs/sessions` 를 제외한다.
- `z.docs` 루트는 git 이 아니다(Planning · Design · Logs 가 독립 저장소). 옮기거나 지울 때 되돌리기가 없다.
- 문서는 마크다운, 이모지 금지, 한글은 그대로(유니코드 이스케이프 금지). 근거는 파일:줄. 에이전트 보고를 옮긴 것은 △, 직접 확인은 ✔.
- 게임 수치(밸런스 · 성능 · 플레이 시간)는 측정한 빌드 · 기기 · 날짜를 함께 적는다. "재미있다"는 플레이검사 체크리스트 결과로 대신한다.

## 프롬프트 작성

## 에이전트 보고
- 서브에이전트 · 조사 에이전트의 보고는 **산출물로 검산한 뒤** 문서에 옮긴다 — 파일을 열고, 컴파일하고, 플레이 화면을 본다. "있다 / 없다 / 완료" 주장은 특히.
- 컴포넌트 · 프리팹이 있어도 씬에 배치되어 동작하지 않으면 기능이 없는 것이다.

## 코드 리뷰
- 코드 리뷰는 세 층이다 — **결정론 게이트**(컴파일 · 테스트 · 빌드, 커밋 전) · **AI 센서**(읽기 전용 에이전트가 결함 후보를 찍어 주의 위치를 알린다 — 판결이 아니다) · **사람 판단**(의도 · 위험 · 되돌리기). 절차 · 센서 구성 · 지적 형식 · 위험 등급은 `z.docs/Defense.Planning/코드리뷰_가이드.md`(EasyCheck X-12 판을 Unity 저장소 하나 기준으로 바꾼 것 — X-03. 게이트 명령은 `Defense.Unity/CLAUDE.md` 「결정론 게이트」 한 곳), 리뷰어 프롬프트는 `z.docs/Defense.Planning/_템플릿/리뷰어_지시.md`.
- 코드를 커밋한 세션은 작업 보고서를 쓰기 전에 `<시작 해시>..HEAD` 에 **세션 센서**(리뷰어 1, 모델 지정)를 띄운다. 범위에 고위험 경로(저장 데이터 포맷 · 재화 · 업그레이드 수치 · 빌드 설정 · 패키지 매니페스트 · 서명 · 스토어 설정 · 배포 — 가이드 5절)가 있으면 **고위험 센서**(성격 다른 리뷰어 2 + 검증 1). 띄우기 전에 저장소 · 범위 · 크기 · 구성 · 예상 에이전트 수를 한 줄 알리고 묻지 않는다. **자원 보호가 자동화보다 우선** — 예상 에이전트 5 초과 · 코드 100파일 초과면 묻고, Fable 세션은 리뷰어를 `opus` · `sonnet` 으로 지정한다.
- 센서는 찾은 것을 전부 보고하고 선별은 세션이 규칙으로 한다. 지적은 파일을 열어 확인한 뒤 고침 · 틀림 · 의도 · 범위 밖으로 닫고, **「틀림 · 의도」는 다른 컨텍스트의 판정 반론을 거친다**. 종료 조건은 `blocking` 0 · `important` 전부 고침 또는 사유. 2라운드는 수정 커밋만 한 번, 3라운드 없음. 센서가 끝나면 원본 · 처리표를 Planning 과제 폴더 `03_작업기록/코드리뷰_<날짜>_<세션>/` 에 남기고(`_도구/센서기록_추출.py` · `처리.md`), 보고 「코드 리뷰」 절은 가이드 8절 형식.
- **사람이 보는 것은 위험 등급이 정한다** — 저: 보고의 증거 3행 · 중: + `blocking` · `important` · `new` 지적과 미해결 · 고: + 바뀐 메서드 블록 직접 읽기 · 되돌리는 법 확인. 지시서로 시작한 세션은 지시서의 「승인 지점」을 따른다.
- 자동 수정 리뷰 · 클라우드 리뷰 · 리뷰어에게 쓰기 권한은 쓰지 않는다.

## 세션 종료
1. 과제 `NOTES.md` 덮어쓰기 3절 갱신 → 2. `결정기록.md` → 3. `작업색인.md` → 4. `Defense.Planning/README.md` 현황판 → 5. 손댄 저장소마다 `git status` 확인 → 6. 푸시 허락 질문(「푸시」 절). 사용자가 답하기 전까지는 푸시하지 않은 상태로 세션 끝 요약에 적는다 → 7. **수행이 끝난 지시서는 `02_계획/지시서/_old/` 로 옮긴다**(`git mv`, 과제 README 표의 링크도 함께). 보류된 지시서는 제자리에 두고 표에 「보류」를 적는다. 세션 로그는 훅이 남긴다 — 세션이 따로 쓰지 않는다.
